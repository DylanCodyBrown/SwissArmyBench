# Use Swiss Army Bench

The person's guide, with a screenshot of each feature, is
[swissarmybench-user-guide.md](swissarmybench-user-guide.md). Answer from it, and point them at the
section that covers their question.

When you are the agent working on their grids (through the swissarmybench MCP server), read its
`swissarmybench://index` resource first (or call the `guide` tool with no arguments): a short index of
the app, its tools by area and the rules. `guide(topic=...)` gives one topic in full (grids, analyze,
relationships, connections, blades, workbench, streamlit, privacy), and `agent_context` says which
table they have in front of them.

## Things people ask that the guide answers

| They ask | Point them at |
|---|---|
| Where are the settings / the theme / the agent's access? | **Settings**, first in the Application row (the top row of the ribbon, on every tab) |
| Where did the column profile go? | Select the column, then Profile on the ribbon's Column row (a popup) |
| How do I compare two tables? | Right-click a table's tab, Compare with… (or drag one tab onto another); the key picker opens with the Key Finder already run and the key unique on both sides ticked |
| Where did a table I closed go? | The ≡ button beside + in the tab strip: Tables lists the closed ones, each with Open (the same table, not a copy) |
| Where are the header profiles / the zoom? | Profiles: the small button in the grid's top-left corner, above the row numbers. Zoom: the Application row (the whole page, Visualizations too) |
| How do I undo a step? / Is there a list of every command? | Ctrl+Z (Ctrl+Y redoes), or hover "N steps" under the title and remove any one. Ctrl+Shift+P lists every action of the page |
| How are my tables related? / Draw an ERD | The rail's ERD, right after Visualizations: Import relationships (a .tang or a model as JSON), apply a shared model, or ask the agent to build one |
| Where did the Sandbox / the Diagram go? | Renamed (2026-11-16): the Sandbox is **Visualizations** and the Diagram is the **ERD**, the same places on the rail. Old addresses, `sab.sandbox(...)` and the agent's `sandbox_*` commands still work for this release; write `sab.visualizations(...)` and `visualizations_*` |
| How do I read a Power BI dataset? / Bring its relationships in / Run DAX | Connections, Add connection, **Power BI workspace**: the workspace id (no dataset: one connection reaches every dataset in the workspace), and an app registration whose tenant id, client id and client secret are entries of their key vault. The catalog shows each dataset with its tables, which open as grids. DAX goes in a **DAX cell** (a cell kind of its own; its picker names a dataset as `Finance/Sales model`) or `sab.dax("Finance/Sales model", "EVALUATE ...")`. **Import its relationships**, on a dataset in the catalog, puts that dataset's joins in the ERD. For you: `connections_datasets` (a workspace's datasets), `connections_import_relationships` with `dataset`, `workbench_dax_add`, and `workbench_run` with kind `dax` and the dataset as `connection` |
| How do I read Dataverse? / Dataverse tables in a notebook / SQL on Dataverse | Connections, Add connection, **Dataverse**: the environment's address and a sign-in (as you, a managed identity, or an app registration whose client secret is a key vault's entry, never typed). Its tables are listed and read on its read-only SQL endpoint (one schema, dbo; a connection saved for the Web API has a one-click switch); `sab.read("Sales CRM", "account")` reads through the Web API (choice columns as labels), `conn.read(table, filter=..., limit=...)` and `conn.fetch(fetch_xml)` in Python. `%%sql Sales CRM` runs T-SQL on its read-only SQL endpoint (needs pyodbc and ODBC Driver 18); when an admin has it off, the error says so and offers the `sab.read` line. For you: `connections_types` (the `dataverse` form), `connections_test`, `connections_create`, `connections_open_table`, `catalog_tables` |
| How do I build a Streamlit app from my data? | In the Workbench, **New app** opens a canvas (a tab, its own `.stapp.json` file). Write Python cells in a notebook (one that calls `st.` shows live in its cell; open tables are DataFrames by name), then drag a cell onto the canvas by its number (or from the canvas's Streamlit cells panel, by its name), or copy it (C) and paste (Ctrl+V): a block that links to the cell, on a 12-column grid. A Markdown or HTML cell goes on too (marked T; `st.markdown` or `st.html` on the page): its `{{ names }}` are reads, so a filter drives its text, escaped as text by the HTML cells' rules. A Markdown cell's ```mermaid block is drawn as a diagram in the notebook (a code block on a Streamlit page). **Play** shows the page live in place, **Edit** goes back; a cell that makes a name (`region = st.selectbox(...)`) drives the blocks that read it. **Export** writes a folder that runs alone; **Save as zip** zips the project (`data.py`, `pages/*.py`). A project starts with `data.ipynb` (New project… in a group's + menu). For you: `workbench_new_app`, `workbench_canvas`, `streamlit_block_place`, `streamlit_block_change`, `workbench_canvas_play`, `streamlit_save`, `streamlit_save_as`, `project_new`, `workbench_cell_name`, `streamlit_cells`, `workbench_pop_out`. `streamlit_export` waits for the user's Allow (it copies the tables' rows), as `table_export` does; `project_new` and `streamlit_save_as` too when data.ipynb would hold a pasted table's rows |
| How do I save my work and open it on another computer? | **Projects (.sab)** in the guide: one file holds the notebooks, scripts, canvases, the open tables (where each came from, with its steps), Visualizations and the relationships. **Save** (Ctrl+S) in the project group of the Application row; **Open project…** on the Start view (the mark). **New project** saves the file first, then offers **Autosave**. The project's notebooks, scripts, apps, connections, blades and dashboards are its own (another project sees none; **Import** copies them in); passwords stay on each computer (a connection without one here says **Needs a password**). A table that cannot come back offers its fix (Add connection, Set the password, Find orders.csv). A pasted table keeps its rows only when ticked in **Save as…**. For you: `project_new(path)`, `project_open`, `project_save`, `project_recent`, `project_table_fix`, `project_autosave`, `project_documents`, `project_import` (`guide(topic="projects")`) |
| How do I schedule a notebook? / Run it in an Azure Function / Export it as one script | The document's **…** menu: **Export as one Python script…** (one .py: `python <file>`, `--install` pips its REQUIREMENTS, `main()` for a timer trigger) or **Export as one notebook…** (one linear .ipynb for nbconvert or papermill). Its connections, key vault lookups (an Azure Key Vault by the function app's managed identity) and grid steps are written out; no passwords, no rows, no Swiss Army Bench. For you: `workbench_export_script(path, format="script" or "notebook")`; what cannot be exported comes back in `problems`, and `stub: true` writes the rest with FILL IN stubs |
| Does my page work for every filter value? / A filter's defaults / This cell does too much | A cell's header line `# Makes: region: str = "All"; by_region: table = orders` is its **contract**: a block whose filter is not on the page reads those defaults (said quietly on the block). **Test this page** (beside Play) runs Streamlit's own test runner with each filter's values and turns the blocks that fail red with the value that broke them. A view that filters, groups or joins a table shows **Move to data.ipynb**: those lines become a named cell of data.ipynb and the view reads them back (`from data import ...`). For you: `streamlit_app` (each block's `controller`, `defaults`, `failures`, `thin`), `streamlit_check`, `streamlit_test`, `workbench_canvas_move_to_data` |
| Where does this value come from? / Check a notebook's results | Right-click a canvas block or a cell and choose **Lineage**: the flow back to the data as a chart, a card per step with its value (a table's rows, first rows and row change; a value; an error in red), live while the app plays. Right-click an output, **Approve the output**: a later run that differs says "Changed since approved" in amber; `python -m swissarmybench.client.standalone x.ipynb --check-approved` checks without the app (exit 1 and a report). For you: `workbench_lineage` (the flow, its Mermaid and each value), `workbench_lineage_show`, `workbench_cell_approve`, `workbench_approvals`, `workbench_approval_check` |
| How do I call a web API (an Azure Function, a Lambda, Firebase)? / Explore an API / Where did Add API go? | The rail's **APIs** page (its Add API: an OpenAPI document by address, file or paste, or the form; a sign-in type or a preset). An API is blades in this computer's library (`~/.swissarmybench/library/apis/<name>/`), never a project's: its API blade and a web call blade per operation (`Orders.list_orders`). The page explores them (search, inputs, outputs, schemas), **Author a call** sends one and opens the answer in **Structures**; **Return as table** on a web call makes it one of the API's tables (`SELECT * FROM list_orders` in `%%sql Orders`, `sab.read("Orders", "list_orders")`). For you: `apis_search`, `apis_describe`, `apis_call`, `apis_save_call` (`as_table`, `records`), `apis_refresh`, `connections_api_add` (`guide(topic="apis")`) |
| Look at a JSON / YAML / XML / TOML file / Edit a config / What did the API answer? | The rail's **Structures** page: a tree and its text side by side, steps (Pick, Filter, Rename, Remove, Set, Add, Sort, Flatten), Open as grid, Save as any of the four; an API's answer keeps its lineage (Run again). `sab.structure("gates")` reads a saved one in code. For you: `structures_open`, `structures_show`, `structures_step_add`, `structures_open_as_grid`, `structures_save`, `structures_lineage` (`guide(topic="structures")`) |
| How do I connect to something that is not a database or a file? (a web service, a vendor library) | Connections, Add connection, **Python (your own code)**: three code boxes (Connect makes `conn`; List the tables returns its catalog; Read a table returns a table's rows) and where each environment variable the code reads comes from (this computer, the keyring, a key vault's entry, a plain value). You can make one for them: `connections_python_variables` finds the names, `connections_python_save` saves it (`test=true` only runs it), `connections_python_tables` lists its tables, `connections_open_table` opens one. In a notebook: `sab.connection("Name")`, `sab.read("Name", "table")` |
| Can I write SQL over my connections? / `SELECT * FROM [Finance Captive].Sales` / join a database with a Power BI dataset | **Your connections in DuckDB SQL** in the guide: name a connection's table as `[Connection].table` (`[Finance Captive]."Sales model".Date` when two datasets share the name) in the **+** tab, a `%%sql` cell on **DuckDB**, or `sab.sql(query)`. Every row the query needs is read (filters sent to the source), once a session (Refresh). The Connections page lists each connection's tables: Open, Copy name, Open all. For you: `tabs_new_query` or `steps_run_sql` with that SQL, `connections_tables`, `connections_open_dataset`, `connections_sql_refresh` |
| My table came from the wrong connection / I deleted a connection and need its tables and queries on another | The Table row's **Connection: <name>**: pick another connection and the table is read again from it, its steps kept (matched by name in any case; not found: pick it from the other's catalog or **Write a query…**; a query is looked over in its own window, then **Run on Trino**; **Undo**). A deleted connection's tables on the strip: **Use another connection…** moves them all; then **Point these at Trino** changes the name in the ticked cells only. For you: `table_connection`, `table_swap_connection`, `table_swap_undo`, `connections_move_tables`, `connections_repoint` |
| Build an Excel workbook from my data / Cession statements or invoices from a template | The **Accounting** extension, when it is on (`app_mode(all=true)` lists the project types): `project_new(folder, name, type="accounting")`; the Excel canvas (`workbook_open`, `workbook_block`, `workbook_play`, `workbook_export`: workbook.py builds the same workbook from data.py anywhere); templates from an existing workbook (`template_import`, `template_bind`); `statements_build` is a dry run unless the user said to build, and then waits for their Allow; `statements_register`. Guide topic: accounting |
| Are there ready-made blades? / Refresh a Power BI dataset from Python / Format an Excel workbook / A DAX or HTML snippet / How do I learn Streamlit here? | The **Starters** at the bottom of the blade list (the guide's "Starter blades"): a read-only pack by family (Power BI, Dataverse, Excel, Files, DAX, HTML, Markdown, Streamlit, Controllers, Text and layout, Components; a Markdown snippet says the names it reads), **Copy as your own** to change one. A Python starter makes a function: `refresh = sab.blade("Power BI refresh dataset")`, `refresh("Sales model")`. A snippet is dragged onto a cell of its language (or the cell's More: Insert a snippet…) and fills its blanks from the cell's dataset or the open tables. The Streamlit pieces are documented for a learner ("Learning Streamlit with the starter pieces"). For you: `blades_starters`, `blades_copy`, `blades_snippet`, `workbench_snippet_insert`; run a Python starter in a kernel (`workbench_run`) |
| What do the colours of the tabs mean? / Run my script like a schedule would / Which cells are stale? / Describe my columns | Kind colours: app pages violet, notebooks blue, scripts green (Settings, Kind colours; `app_kind_colours`). Each document has its mode's panels (the status bar's toggles): an app's **Properties** (a block, else the page settings: `streamlit_page_settings`) and **State** (`streamlit_state`); a notebook's **Outline**, edited and out-of-date cells and **Run up to here** (`workbench_window` "notebook.runOrder", "run.upToHere"); a script's **Run settings**, **Run as scheduled** and **Run history** (`workbench_script_settings`, `workbench_script_run`, `workbench_script_history`); data.ipynb's **Dictionary** ("data.view", "dictionary.describe"; `project_dictionary`) |
| Something is broken / here is a bug / I left a note | `app_beta_notes` (their notes: words, the element, the last actions), then `app_beta_log(kind="error")` for the stacks (a note's `server_errors` names them). The user can send the zip: Settings, Beta, Export beta log…. `app_beta_mode` turns beta mode off or on |
| Open Claude on this / Launch Claude Code or Claude Desktop | The guide's "Launch Claude": the status bar's Launch Claude (Claude Code in their terminal in a folder with the context, or Claude Desktop with the MCP server added; Settings, Claude: which one, bypass permissions). For you: `app_claude` reads what is installed and `app_context` the live context.md (connections and their SQL names, open tables, the ERD, variables, documents, the tool guide); launching and its settings are the user's alone |
| "X needs a package" / A package is missing / Install a driver | The window that came up: **Install now** (uv, into the app's Python, or the notebook's or Streamlit app's), then it carries on; **Not now** leaves an **Install <package>** button there. For you: an answer's `missing` {feature, packages, python, command}: `python` "app" is `blades_install`, a Streamlit app's is `streamlit_install`, a notebook's is `%pip install` in its kernel (`workbench_run`); then do it again |
| What extensions are there? / Install one | The guide's "Extensions": the rail's Extensions page (Streamlit preinstalled, removable; Accounting and Power Apps available). For you: `extensions_list`, `extensions_install` and `extensions_remove` (each waits for their Allow, then the app restarts) |
| Is there an update? / Update the app / Stop it starting at sign-in / Where did the app go? | The guide's "Tray and updates": the tray icon (a click opens the page; right-click for what is open, Restart, Start with Windows, Stop and quit), "Update available" in the status bars, Settings' Check for updates. For you: `app_update_check`, `app_update` (waits for their Allow, then the app restarts), `app_autostart`. A stopped app: `swissarmybench start` (or the tray's Start) |
| How do I get back to the start? / There is no back button / Where am I? | The guide's "Getting around": the rail down the left, in the order of the work (Connections, Variables, Grids, ERD, APIs, Structures, Blades, Notebooks, Scripts, Apps, Visualizations, Session, Settings; right-click a code area for a new window); the mark at the top left of every window goes home (Alt+Home); the browser's Back and Forward move between tabs, Connections' forms and catalog views, and a reload keeps the view; Back buttons name where they go; a trail past one level. For you: `app_navigate` (home, back, forward, any rail area, a view; `new_window` for notebooks, scripts, apps), and the Workbench's `workbench_window` "nav.home" / "nav.back" |
| Where do my variables come from? / Add an environment variable / I imported a key vault and have lots of variables | The rail's **Variables** page: every variable this computer gives or something reads, by source (key vault, plain value, keyring, environment, not set), each with what uses it; **Add variable** (a plain value, this computer only, or the keyring for a secret); Edit, Rename, Remove; its **Key vaults** and **Add key vault**. The library's, not a project's. For you: `variables_list`, `variables_set` (`kept="keyring"`: you may set a secret, never read it), `variables_rename`, `variables_remove` |
| Where are my connections kept? / Share connections with my team / Use a team's library / Put it in GitHub | Your **library**: connections, APIs, key vaults, blades, tangs, variables and colours, outside every project, one text file each in a folder made to be a Git repository (`~/.swissarmybench/library`; Settings, **Library**, **Change…** points it at a clone). No password, secret, token or row is ever in it; a clone asks for each missing password. Commit and push it with your own Git. For you: `library_info`, `library_set_folder` (waits for the user's Allow), `guide(topic="library")` |
| What did the agent just do? / Watch the agent work / Stop the page jumping | The rail's **Session** page: this session's log of what the agent made or changed, each line a link to the thing (The agent / Me / Both). **Follow the agent** (there and in Settings, on by default) brings each change to the front and highlights it, never while you type; turn it off and the Session icon counts them instead. For you: `app_session` reads the log and the switch (the switch is the user's) |
| Build a Power Apps code app / Push my app / Make a custom connector | The guide's "Power Apps (an extension)": the rail's **Code App** page, when the extension is installed (New code app, sources, connectors, Run live, Push, Custom connector, Runs). For you: `guide(topic="powerapps")` and the `powerapps_` tools; Push, a custom connector and installs wait for their Allow |
| What can the agent see? | What the agent may do: everything they can (the golden rule), through the MCP: grids, connections, blades, the Workbench's notebooks, scripts and kernels, environments. Its exports still wait for their Allow; it never gets a password's value; Settings lists its activity |

## Do not

- Don't approve your own export. The Allow click is theirs, and the server refuses an agent that
  tries.
- Don't ask for or print a password. Connections and blades read theirs from the keyring, an
  environment variable or a vault; set where one comes from with `connections_password_source`.
- Don't paste their table's values into the chat to "show" them something; open or filter the grid
  instead (`steps_put` or `steps_add`), so the data stays on their machine.
